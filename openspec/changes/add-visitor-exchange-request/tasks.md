## 1. 换货资格与提交

- [x] 1.1 顾客在自己的订单卡片上核对换货资格并预览摘要（React 表单、Fastify 资格用例、签收时间迁移与 FAQ 出处）。验收支持迁移前已有的演示订单，合格时显示确认摘要和两类运费说明，第 7 天可申请、第 8 天提示逾期，未签收或商品条件不满足时显示对应原因，访客之间隔离且全过程无需模型。
- [x] 1.2 顾客明确确认后提交一笔换货申请（确认按钮、服务端同源与归属检查、资格复核、SQLite 幂等事务）。验收有效确认返回申请编号与「已提交」，同一确认重复和并发返回同一编号，过期或被替换的摘要、资格变化、跨来源以及其他访客的确认都无法创建申请。依赖 1.1。

## 2. 申请结果恢复

- [ ] 2.1 顾客在响应中断后恢复申请结果（页面重试、订单卡片回执、Docker 数据卷冒烟）。验收服务端已写入但响应丢失时重试原确认得到同一编号，刷新与容器重建后原会话查单可以看到原申请，独立会话看不到其他访客的申请。依赖 1.2。

## 3. 对话内办理换货

- [ ] 3.1 顾客在同一个对话里完成换货（React 消息列表、服务端状态机、复用资格预览和提交）。验收「我想换货」后逐轮补充原因和商品申报，插问 FAQ 后可继续，查单补问和换货不会同时推进。聊天文本「确认」只给操作提示，点击摘要按钮才返回申请编号。依赖 2.1。
- [ ] 3.2 顾客从中断处继续或取消尚未提交的换货（SQLite 办理进度、同源对话请求和摘要撤销）。验收刷新后用「继续换货」恢复原步骤，另一个访客无法恢复该进度，取消后旧摘要无法提交，原有回执恢复场景继续可用。依赖 3.1。
