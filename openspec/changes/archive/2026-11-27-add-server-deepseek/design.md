## Context

当前 FAQ 有稳定的条目标识、结论和政策摘录。工作区还包含未交付的浏览器 DeepSeek 实现。此次迁移复用 FAQ 检索、主题判断和原问题重试等行为，把模型请求和候选管理放入 Fastify。

## Goals / Non-Goals

**Goals**

- 公开演示不开启计费模型也能完成既有政策问答。
- 受控实例能展示经过证据校验的生成正文、政策引用及本轮来源。
- 部署者 Key 由服务端运行时持有，浏览器升级后清理旧版凭证存储。

**Non-Goals**

- 公网计费模式和访客配额管理按独立需求评估。订单工具、换货 Flow 和逐段流式协议留给各自后续 Change。

## Decisions

### 目录落点与模块职责

当前 `App.tsx` 集中了浏览器凭证、两条请求链、交互状态和结果渲染。`shared/chat.ts` 同时暴露了站内协议和 DeepSeek 响应结构。迁移时把这些职责收敛到以下入口：

```text
src/
  web/
    App.tsx                 顾客问答页面和展示入口
    chat/use-chat.ts        同源提交、请求取消、结果状态和按原问题重试
  server/
    index.ts                读取部署配置并启动服务
    app.ts                  装配 Fastify、健康检查和问答路由
    config.ts               解析运行时模式与凭证
    chat/
      route.ts              解析站内请求并返回 HTTP 响应
      answer-question.ts    编排预置、生成、澄清和降级
    faq/                    复用语料、检索、候选和出处构造
    deepseek/client.ts      负责官方请求、上游协议解析和超时
  shared/chat.ts            POST /api/chat 的站内契约
tests/                     保留既有测试入口，按用户行为增补用例
```

- 问答用例提供一个接收问题并返回问答结果的入口。路由通过同一入口覆盖预置、生成和降级，模型调用接口由装配层提供。生产使用 DeepSeek，测试使用可控替身。
- FAQ 的上下文在服务端复用，作为问答用例的内部输入。模型专用请求与响应结构位于 `server/deepseek/`，由适配代码转换成稳定结果。政策结论校验留在服务端问答路径，网页按站内响应显示正文、引用和来源。
- 目录按现有任务落地。1.1 收敛页上状态和同源路由，1.2 加入运行时配置和模型调用，2.1 与 2.2 在相同入口补齐证据和失败路径。沿用现有 Vite 根目录、Fastify 启动点、Docker 布局和测试目录。查单、换货和转人工在各自 Change 实现时添加模块。

### 单一问答入口与部署模式

- 网页继续提交 `POST /api/chat { question }`。保留既有答复字段，在返回结果中附加本轮来源 `preset`、`generated` 或 `fallback`，供页面标记预置、模型生成或降级。
- 运行时 `CHAT_MODE` 默认 `preset`，公开演示以该模式验收。受控本地或私有实例显式设置 `CHAT_MODE=deepseek` 和 `DEEPSEEK_API_KEY`。真实模式缺少 Key 时向部署者报告配置错误，错误只包含变量名。请求字段不能改变部署模式。
- 迁移完成后，模型、候选和响应校验由服务端接入。清理旧的候选接口和浏览器直连逻辑。页面初始化时只删除旧存储项 `shopcare:deepseek-key`，无需读取它的值。

### 后端生成与证据校验

1. 先复用现有检索。唯一明确命中时只使用该条目的事实和摘录。关键词未命中、售后主题明确时使用该主题下的有限候选。已知歧义或主题不清时直接引导澄清。复用对否定疑问句和双重否定的主题判断。
2. 后端用运行时 Key 调用 DeepSeek 官方 Chat Completions，一轮至多一次。输入为本轮问题和有限的合成政策证据。使用有限输入、输出预算和覆盖读取响应体的超时。先返回完整 JSON，便于校验后再展示。配置参考 [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。
3. 结构化结果为 `answered` 加 `faqId`、`evidenceQuote`、`answer`，或 `insufficient_evidence`。服务端验证结构、候选成员身份和引文是否确实出自该条目，再回填语料中的原始标题和摘录。当前用例至少校验期限、起算点和费用承担等政策事实。无法核对的结论进入降级或澄清分支。
4. 正文采用通过校验的模型表述。自动化用与预置答案措辞不同的替身结果，确认页面实际展示生成正文和同源引用。用错写 14 天、错误出处或越界 ID 的例子测试拒绝路径。

### 凭证与失败恢复

- 运行时 Key 仅进入服务端发往 DeepSeek 官方 HTTPS 端点的鉴权头。浏览器产物、API 响应、日志、追踪、仓库和镜像构建均排除 Key。容器在运行时注入配置。
- 如果上游失败或回答校验不通过，而现有检索能独立确定同一政策，返回该政策的确定性答复并标注降级。缺少明确依据时显示澄清或可重试错误。浏览器展示应用定义的错误原因。
- 维持失败卡片中原请求问题的快照。顾客可继续编辑草稿。重试重新发送失败问题，并保留新草稿。
- CI 用占位 Key 和请求替身。功能验收包括无 Key 容器冒烟、浏览器与本站请求边界，以及服务端上游地址、鉴权头和响应校验。有效 Key 由部署者在测试实例配置，实际模型正例单独验收。

## Risks / Trade-offs

- 引用存在和结构有效只能确认出处一致。当前合成语料按可复验的政策事实做保守检查，后续评测量化生成质量和覆盖率。
- 完整 JSON 校验会让答复等到生成结束才展示。界面保留等待状态，服务端把请求与响应体读取都计入超时。
- 公开与受控模型实例通过部署配置隔离。公开实例默认预置，受控实例避免向匿名公网开放计费端点。

## Migration Plan

验收现有预置问答后，移除浏览器侧旧凭证和候选请求。上线公开实例时使用默认模式。受控环境从服务端注入 Key 启用生成。出现上游问题时将该部署切回 `preset` 即可恢复预置。
