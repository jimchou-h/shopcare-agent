## Why

售后政策可以解释换货规则，实际服务还需要知道顾客的订单处于什么状态。先交付一条可部署、可验证归属的只读查单路径，为下一轮换货资格判断提供可信的订单数据。

## What Changes

- 访客可在现有问答页领取自己的合成示例订单，并在同一个输入框发起查询。回复展示订单号、商品和订单状态。
- 查询缺单号时提示补充。顾客可在下一轮直接输入单号，补问状态只属于当前演示会话。
- 服务端识别访客会话，在 SQLite 中按访客归属读取订单。其他访客的单号与不存在的单号得到相同的无结果反馈。
- 同一个浏览器在会话有效期内可刷新或在容器重建后继续查单。公开演示在无模型 Key 的环境中覆盖整个流程。
- 本轮业务范围为演示订单查询和补问。换货资格、业务写入、人工坐席和真实订单接入各自独立规划。

## Impact

- React 继续使用现有问答页。Fastify 在同源 API 下提供演示会话入口，并将查单请求交给服务端订单用例。
- SQLite 引入可重复执行的迁移，Docker Compose 提供持久数据卷。[现有 FAQ 规格](../../specs/grounded-faq/spec.md)继续适用。
- 开发顺序接在 `add-server-deepseek` 验收归档之后。订单状态将供后续换货 Flow 复用。
