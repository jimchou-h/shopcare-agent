## Context

当前 React 页面通过同源 `POST /api/chat` 查询 FAQ。Fastify 在启动时装配问答用例，公开演示默认使用预置模式。查单将复用输入框和请求生命周期，新增可验证归属的订单读取与少量补问状态。

## Goals / Non-Goals

**Goals**

- 无需注册或模型 Key 即可走通「领取示例订单 → 对话中查询 → 查看状态」。
- 同一浏览器在会话有效期内可以跨页面刷新和容器重建继续查单。用两个独立浏览器会话可以复验数据隔离。
- 让后续的换货资格用例通过服务端订单接口读取可信状态。

**Non-Goals**

- 业务范围限于合成订单的只读查询。换货申请及持久化写入、模拟坐席、跨设备身份和完整对话历史各自独立规划。

## Decisions

### 入口与问答编排

- 在现有页面放一个「领取示例订单」入口。点击后通过同源 `POST /api/demo/session` 创建或复用演示会话，展示关联的示例单号，提供「查询示例订单」快捷操作，将查询填入现有输入框。首次领取请求进行时禁止重复提交。
- 继续使用 `POST /api/chat { question }`。Fastify 在 FAQ 或模型调用前，通过明确的查单用语或等待补单号的状态判定本轮意图。FAQ 路径继续使用已有配置和响应；查单返回独立、可校验的结果类型，由 React 显示订单号、商品名和状态，或显示待补单号、未找到、需领取订单等引导。
- 查单输入支持「查订单」「查订单 SC-AB12CD34EF56」等明确问法。演示单号固定为 `SC-` 加 12 位英文字母或数字，查询时去掉首尾空白并统一大小写。单独的合法单号只在等待补单号时消费。遇到多个单号或同一轮混合单号与政策问题时提示分开提问。包含可识别演示单号的消息由本地处理。普通的「签收后几天可以换货？」继续进入 FAQ。
- 查单与补问由服务端规则执行。订单详情、识别到的演示单号和会话凭证不加入模型请求，即使部署启用了 DeepSeek。

### 会话、归属与补问

- 会话由服务端生成不可预测的随机令牌，放入 `HttpOnly`、`SameSite=Lax` 的同源 Cookie，HTTPS 部署使用 `Secure`。服务端存令牌摘要和到期时间，以 24 小时固定有效期作为演示默认值。Cookie 缺失或过期时引导领取新的示例订单。
- 领取示例订单时，在同一事务里创建会话并绑定一笔已签收的合成订单。同一有效 Cookie 重复或并行领取时均返回同一个单号。订单号用于定位记录，归属通过 `visitorId` 与订单号共同查询。查询失败统一提示「未找到可查询的订单」，避免通过响应判断其他会话中的订单是否存在。
- 缺单号的明确查单将会话置为等待补充单号。顾客补单号成功后清除状态。补充内容像单号但格式错误，例如 `SC-123`，或查询无结果时保留状态。新话题按已有问答流程处理并结束待补，包括需要语义理解的政策问法。SQLite 只保存支撑跨轮查询所需的待补状态和订单数据。
- 创建会话、变更补问状态的请求校验同源来源。普通无会话 FAQ 继续兼容现有请求。公开入口限制请求体大小和频率，领取会话时清理过期会话及其演示订单。日志和响应避免携带 Cookie 令牌、摘要和存储诊断细节。

### 模块与持久化

- `src/server/orders/` 负责查单用例、订单归属查询和合成种子；`src/server/demo-session/` 负责访客身份和补问状态；`src/server/db/` 负责 SQLite 连接与迁移。问答用例负责分发，供应商客户端留在已有目录。浏览器只消费 `src/shared/` 中约定的站内契约。
- 迁移创建演示会话和订单表，保留外键、唯一约束和迁移版本。SQLite 由应用装配层初始化并在应用关闭时释放。Docker Compose 将数据库写到持久卷，运行用户拥有数据目录写权限。单实例部署即可覆盖本轮，保留现有健康检查入口并验证存储初始化。
- 验证沿用 Fastify `inject`、React 行为测试和容器冒烟。隔离测试使用两个独立的会话 Cookie；重建测试使用临时数据库或隔离的 Compose 数据卷，对照重建前后的同一单号和待补状态。

## Risks / Trade-offs

- 查单先使用明确短语和单号格式，覆盖范围由规格示例界定。新增问法通过实际入口测试扩展，降低 FAQ 被误路由的概率。
- 演示身份依赖当前浏览器与 Cookie，有效期内可恢复。无 Cookie 或会话到期时重新领取合成示例，减少公开演示状态积累。
- SQLite 采用单实例持久卷，数据库和归属检查留在服务端。部署时验证首次迁移、容器重建和无写权限时的失败信号。

## Migration Plan

按现有 Docker Compose 部署方式升级，首次启动自动迁移空数据库。保留数据卷重建应用容器时执行恢复验收。回滚应用镜像时保留独立数据卷，恢复查单版本后可继续使用尚未过期的会话。
